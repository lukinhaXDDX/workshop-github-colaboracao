# Configuração antes do workshop

Este pacote contém os arquivos do repositório. **Labels, permissões e issues reais precisam ser criadas no GitHub**.

## Publicar
1. Crie um repositório **público** chamado `workshop-github-colaboracao`, com a branch padrão `main`.
2. Envie o conteúdo desta pasta para a raiz do repositório (não envie o ZIP como um único arquivo).
3. Confira se `README.md`, `CONTRIBUTING.md`, `participantes/` e `.github/ISSUE_TEMPLATE/` aparecem no GitHub.
4. Ative Issues em **Settings > General > Features**, se necessário.

## Labels
Em **Issues > Labels > New label**, crie:
- `exercício` — verde
- `documentação` — roxo
- `boa primeira issue` — amarelo
- `dúvida` — azul

## Permissões
O roteiro designa Leandro como responsável por permissões, labels e merges. Adicione os apresentadores com acesso de escrita ou superior. Em organizações, use Write/Maintain conforme o papel; em contas pessoais, configure os acessos disponíveis em **Settings > Collaborators**. Participantes podem contribuir via fork sem acesso de escrita.

## Issue de demonstração
Em **Issues > New issue**, use o conteúdo de `exemplos/issue-modelo.md` e aplique `exercício` e `boa primeira issue`. Reserve `participantes/demo.md` para a demonstração ao vivo.

## Antes de começar
- Teste duas contas/perfis, um autor e outro revisor.
- Verifique GitHub Desktop, projetor, conexão e zoom.
- Não faça o fork da demonstração antes do momento previsto no roteiro.
- Confira que as duplas têm arquivos diferentes.
